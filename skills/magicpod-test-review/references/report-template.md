# レポートのテンプレート

レビュー結果は、人が読む「レポート」と、修正に使う「修正の一覧」の2つのファイルに分けて作る。`[ ]` の部分を埋める。

## 1. レポート（`magicpod-test-review_YYYY-MM-DD.md`）

観点別の詳細には、指摘があるテストケースだけを書いてよい。レポートを読むのは skill の中身を知らない人なので、「ステップ5」のような skill 内部の言葉は使わない。

````markdown
# MagicPodテストケースレビュー結果

**レビュー対象:** [対象の説明（例：2026-10-27に作成されたテストケース）] の N 件（[組織名] / [プロジェクト名]）
**レビュー日:** YYYY-MM-DD
**結果:** N件中 OK X件 ／ 要対応 Y件 ／ 要確認 Z件

（直近の実行が失敗しているテストケースがあれば、ここに ⚠️ を付けて、失敗しているテストケース・いつから・失敗の理由（テストの問題か、サイト・アプリなど環境の問題か）を書く。レビューの指摘より先に対応が必要なため、いちばん上に置く）

（OK：要対応・要確認に当たらない。要対応：✗ がある、または優先度「高」の観点（1・2・10）に △ がある。要確認：「要確認」の判定がある。要対応と要確認の両方に当たるものは要対応に数える）

## このレビューで見た観点

| 観点 | 何を見るか | 優先度 |
|---|---|:-:|
| 1. 目的を達成しているか | 確かめたいことを確認するステップがあるか（操作だけで終わっていないか） | 高 |
| 2. 不具合を検知できるアサーションか | 不具合が起きたときに、確認のステップがきちんと失敗するか | 高 |
| 3. 待機コマンド | 実行履歴を見て、待機が足りずに失敗している箇所がないか | 中 |
| 4. 固定時間待機がないか | 「〇秒待つ」を理由なく使っていないか | 中 |
| 5. ロケーターの安定性 | 画面の小さな変更で壊れやすい要素の指定（位置に頼ったXPathなど）がないか | 中 |
| 6. 名前と説明 | テストケース名と説明欄で、テストの目的が分かるか | 低 |
| 7. ステップの読みやすさ | UI要素名やコメントで、ほかの人が読んでも流れが分かるか | 低 |
| 8. 200ステップ以下か | 長すぎて読みにくく、壊れやすくなっていないか | 低 |
| 9. 共有ステップの活用 | 同じ手順を複数のテストにそのまま書いていないか | 中 |
| 10. 依存性がないか | ほかのテスト・初期データ・アカウントの状態に頼らず、単独で動くか | 高 |

（観点を絞った場合は、見た観点の行だけを残す。見ていない観点は表に入れず、表の下に「今回見ていない観点：観点3（待機）、観点4（固定時間待機）…」と1行で書く。チームのガイドラインを使った場合は、使ったルールもここに1〜2行で書く）

## 観点サマリー

| 観点 | TC[番号] | TC[番号] | ... |
|---|:-:|:-:|:-:|
| 1. 目的を達成しているか | ◯ | ◯ | ... |
| 2. 不具合を検知できるアサーションか | ◯ | △ | ... |
| 3. 待機コマンド（実行履歴から判定） | ✗ | 対象外 | ... |
| 4. 固定時間待機がないか | ◯ | ◯ | ... |
| 5. ロケーターの安定性 | △ | ◯ | ... |
| 6. 名前と説明 | △ | △ | ... |
| 7. ステップの読みやすさ | ◯ | ◯ | ... |
| 8. 200ステップ以下か | ◯ | ◯ | ... |
| 9. 共有ステップの活用 | ✗ | ✗ | ... |
| 10. 依存性がないか | ◯ | ◯ | ... |

凡例: ◯ 問題なし / △ 改善の余地あり / ✗ 要改善 / 要確認 意図を確認したい / 対象外 判定に必要な情報がない（実行履歴なしなど）

（見ていない観点は表に入れない）
（全件◯の観点は表から外し、ここに内容つきで1行で書く。例：全件問題なし：観点4（固定時間待機なし）、観点8（200ステップ以下）。観点3が全件「対象外」なら「実行履歴がたまってから再レビューすると判定できる」と添える）
（対象が10件を超える場合や、全件に共通する指摘（説明欄が空など）がある場合は、ここに全体傾向として1回だけ書く）
````

## 2. 修正の一覧（`magicpod-test-review_YYYY-MM-DD_fixes.md`）

修正するときに、レポート全体を読まずに済むようにするためのファイル。説明は書かず、直すために必要な情報だけを並べる。

````markdown
# 修正の一覧（YYYY-MM-DD のレビュー）

**組織 / プロジェクト:** [組織名] / [プロジェクト名]　**レビューしたブランチ:** [ブランチ名、またはデフォルトブランチ]

| # | TC | 観点 | 対象のステップ（引用） | 直し方 | 分類 | 状態 |
|---|---|---|---|---|---|---|
| 1 | [番号] | [観点番号] | `[ステップの引用]` | [具体的な直し方。例：`contains 4` → `equals 4`] | ブランチ上で直せる／デフォルトブランチでしか直せない／方針の判断が必要 | 未対応 |

状態：未対応 ／ 修正済み ／ 対応しない
````

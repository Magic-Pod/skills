# MagicPod スモークテスト作成

MagicPod MCP Server のツールを使って、アプリの核心機能を確かめるスモークテストを設計し、MagicPod に登録する。

## 前提確認

まず MagicPod MCP Server のツールが使えるか確認する。

使えない場合は、次の案内をユーザーに伝えて止まる（API トークンをチャットに貼ってもらわない）。

```
MagicPod MCP Server が設定されていないようです。
次のヘルプページの手順でセットアップしてから、もう一度お試しください。
https://support.magic-pod.com/hc/articles/46186888063769
```

ツールが使える場合は、テストケースの作成に入る前に MagicPod MCP Server の `start_session` を呼び、返ってくるガイダンス（ツールの使い方、コマンドの書き方）に従う。

## ステップ 1: テスト情報のヒアリング

ユーザーの依頼にテスト対象が書かれていればそれを使う。足りない情報は、1〜2 項目ずつ簡潔に聞く（まとめて聞かない）。

1. **テスト対象**：URL、アプリ名、または画面名
2. **登録先**：MagicPod の組織とプロジェクト。分からない場合は、MCP の一覧系ツールで候補を出して選んでもらう
3. **確認したいこと**：例）ログインできる、一覧が表示される、主要な登録・購入の流れが通る
4. **ソースコードの場所**（任意）：リポジトリのパスや URL。分かればシナリオの精度が上がる

## ステップ 2: シナリオの設計

ソースコードにアクセスできる場合は、設計の前に次を確認する。

- **画面・ルーティング構成**：どのページ・画面があるか
- **UI 要素の識別子**：id、name、data-testid、aria-label、アクセシビリティ ID など、実装されている値
- **入力の仕様**：必須項目、入力制約、エラーメッセージの文言
- **テストデータ**：テスト用ユーザーやサンプルデータ（fixture、seed など）
- **既存のテスト**：すでにあるテストでカバーされている範囲（重複を避ける）

ソースコードにアクセスできない場合は、対象の画面を実際に確認するか、主要な UI 要素・データをユーザーに聞き取る。推測した値は使わず、確認できた値を使う。

参照したファイルや実装の内容は、シナリオ提案のときに短く共有する。

スモークテストの原則：

- アプリの**核心機能**だけを確かめる（網羅しない）
- 1 テストあたり 5〜15 ステップ程度にする
- 各テストは単独で実行できるようにする
- 失敗したときに原因が分かる確認ステップを入れる

典型的な構成：

```
テスト1: 表示の確認
  - URL にアクセス / アプリを起動
  - 主要な要素が表示されていることを確認

テスト2: 主要機能の確認
  - ログイン
  - コアとなる操作（検索、登録など）
  - 成功した状態を確認

テスト3: 画面遷移の確認
  - 主要な画面間の移動
  - 戻る操作・ナビゲーション
```

提案したシナリオをユーザーに確認してもらってから次に進む。

## ステップ 3: MagicPod への登録

確認が取れたら、`start_session` のガイダンスに沿って MagicPod MCP Server のツールでテストケースを作成する。

- ステップには、操作（クリック・タップ、入力、確認など）、対象の UI 要素、期待値を入れる
- ユーザーが希望すれば、作成後にテストを実行して結果を確認する

## ステップ 4: 結果の報告

作成したテストをまとめて報告する。

```
## 作成したスモークテスト

| テスト名 | ステップ数 | 確認内容 |
|---------|-----------|---------|
| ...     | ...       | ...     |

MagicPod プロジェクト: [組織名 / プロジェクト名]
テストケースの URL: [取得できた場合]
参照したソースコード: [ファイルパス・リポジトリ]

次のステップ:
- MagicPod の画面でテストを確認・調整できます
- 定期実行や CI への組み込みは、MagicPod の一括実行設定や Web API を利用してください
```

## うまくいかないとき

- MCP のツールが失敗したら、エラー内容をそのまま伝え、同じ呼び出しを何度も繰り返さない
- テスト対象の URL にアクセスできない場合は、URL やネットワーク条件を確認してもらう
- 権限エラーの場合は、API トークンや組織・プロジェクトの権限を確認してもらう

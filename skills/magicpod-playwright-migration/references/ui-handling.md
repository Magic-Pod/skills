# UIの扱い

## 共有UIにするもの

- **複数のテストケースに出てくる画面**は、`capture_ui` を `save_as_shared=True` で取り込み、共有UIにする。取り込んだら、手順2で展開した**全テスト**のうち、その画面で使う要素を洗い出し、名前変更とロケーター追加を `edit_ui_elements` で一度に済ませる。元のコードにない確認のための要素は作らない（例：7件しかない一覧の「8件目」）
- 1つのテストケースでしか使わない画面は、通常のUIとして取り込む。通常のUIは、他のテストケースで使わない
- 共有UIは他のテストケースから参照してよい（`read_test_case` の「uiId を別のテストケースで使わないこと」という警告の例外）

## ヘッダーなど、複数の画面に共通する部分

- ヘッダー用の共有UIを1つ決めて、どの画面のテストケースからもその要素を使う。画面ごとの共有UIに入っているヘッダーの要素は使わない（ヘッダーが変わったときに直す場所が散らばるため）
- 既存のヘッダー用の共有UIは、計画を作る前に探す。ヘッダーを操作する既存の共有ステップ（「［ヘッダー］…」など）の中身を `read_shared_step` / `get_shared_step_internal_steps` で読み、使っているUIのIDを確かめる。ログイン済みと未ログインで分かれていることがある。要素は `inspect_ui`（mode=`search`）で確かめる
- 既存のヘッダー用の共有UIがなければ、ヘッダーのためだけに同じ画面を取り込み直さない。最初に取り込んだ画面の共有UIの中のヘッダー要素に「ヘッダー_…」と名前を付け、それをヘッダー用として使い回す（同じ画面の共有UIが2つにならないように）

## 取り込むタイミングと状態

- 共有UIにする画面と、どの状態で取り込むか（メニューを開いた後、カートに2商品を入れた後など）を、手順2で決める。計画の「共有ステップ・共有UI」の表に書く
- 最初のテストケースのステップを作る前に、決めた状態でまとめて取り込み、名前変更とロケーター追加を済ませる。途中で取り込むと、後から要素を足すことになり、UIのIDが変わって古いUIが残る
- 取り込む画面まで進めるには、最初のテストケースに一時的な遷移ステップ（`navigate_to_url`、ログインの操作など）を足して実行し、取り込んだら消す。端末には前の画面のログイン状態などが残るので、取り込みたい状態（未ログインなど）になっているかを確かめ、違えば一時的に `clear_cookies` などで整える
- 画面に出ていない要素（画面の下のほう、操作の後で現れる要素、`<head>` 内など）は、locator-mapping.md の「取り込まれない要素の扱い」に従う

## 編集するとIDが変わる

- `edit_ui_elements` を使うと、UIのIDが変わる。名前変更とロケーター追加は、ステップを作る前に済ませる
- 後から変えた場合も、既存のステップは古いIDのままで動く。新しく作るステップには新しいIDを使う。前の回（別の依頼）で作った共有UIに今回要素を足すのもよい。報告書に新旧のIDを書き、進捗メモのIDを最新にする
- 不要になったUI（確かめるために取り込んだだけのもの、参照するステップを消したもの）は `delete_ui` で消す。共有UIは `test_case_number` なしで消せる。参照しているステップが残っていると「Used in test case …」で消せない
- 編集前の古い版のIDは、単独では消せない（「UI is not the latest one」）。最新版のIDで消すとUIごと消える。最新版を使っているなら、古い版は残したままでよい（実行には影響しない）
- 編集のエラー（「This UI has already been edited」など）は mcp-notes.md

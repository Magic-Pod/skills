# サブエージェントを使うとき

手順4でユーザーがサブエージェントを使うことを選んだ場合だけ、この手順に従う。

## 選んでもらうときに示す違い（手順4の8）

- 時間：同時に動かしても、テストケースを作るときに使える端末の数に上限があり（例：3台）、終了した端末もすぐには空かないので、速くなる幅は小さい
- トークン：どちらでも `start_session`（1回あたり約30KB、約8〜9千トークン）を件数分呼ぶので、件数に比例して増える。サブエージェントを使うと、進めるエージェントの文脈は節約できる。総量の差は計っていない
- 端末：サブエージェントの数だけ端末を同時に使う。テストケースを作るときに使える端末は組織で共有しているので、ほかの人の作業や実行に影響しうる
- 準備：使う場合は、メインのエージェントが先に、テストケースの作成と設定、共有UIの整備、引き継ぎ用ファイルを作る

## 準備（メインのエージェント）

- 変換計画（手順4）の承認、テストケースの作成と設定（開始方法・説明欄の変換元の1行）、共有ステップの作成、共有UIの取り込みと要素の追加を先に済ませる。サブエージェントが使うUIのIDは、ここで固定する
- 同じデータを作る・変える・消すテストケース（shared-steps-and-variables.md の「投入の順序」）は、同じサブエージェントに順番どおりに担当させ、並列にしない
- **引き継ぎ用のファイルを1つ作り、各サブエージェントに同じものを渡す。** 共有UIの要素IDの表、共有ステップの番号、テスト設定の番号、ユーザーと決めたこと、テストケースごとの**ステップの設計**（コマンド・要素ID・値・コメントの文言・説明欄に書くこと）

## サブエージェントが守ること

- 共有UIを `edit_ui_elements` で編集しない（ほかのサブエージェントのステップが古いIDを参照するため）
- 共有ステップを作らない・編集しない
- 足りない要素は、そのテストケースだけの通常UIとして取り込む
- 担当外のテストケースに触れない。進捗は自分用のファイルに書く
- 自分のセッションで起動した端末は、テストケースごとの作業の最後に `terminate` する

## 同時に動かす数

- 2つを推奨
- 端末の空きが足りなくなりやすい。空き待ちの対処は mcp-notes.md

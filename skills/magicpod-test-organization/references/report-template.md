# 報告の形

## 診断

```markdown
## {表示名}（{プロジェクト名}） の整理の診断

**結論**：{いちばん効く整理を1〜2文で。例：一括実行の対象がはっきりしないので、まずラベルで「毎日回すもの」を決めるのがおすすめです。}

テストケース {N} 件 ／ フォルダ {N} 個 ／ ラベル {N} 個 ／ 共有ステップ {N} 個

| 観点 | 状態 | 気になる点 |
|---|---|---|
| 命名 | {良い／要整理} | {例：同じ名前のテストが2組、中身が分からない名前が3件} |
| フォルダ | | |
| ラベル | | |
| 共有ステップ | | |
| 重複ステップ | | {推測であることを書く} |
| 説明欄 | | {例：空が 25 件中 24 件} |
| 一括実行 | | {例：どの一括実行でも動いていないテストが 8 件} |
| 棚卸しの候補 | | {例：ステップ 0 件が1件} |

**おすすめの順番**
1. {例：ルールを決める（命名・フォルダ・ラベル）}
2. {…}

どれから進めますか？
```

- 状態は「良い」「要整理」の2つで十分。点数は付けない。
- 気になる点には、件数と代表例（テストケースへのリンク）を付ける。全部は並べない。
- ルールのファイル（`MAGICPOD_CONVENTIONS.md`）を読んだ場合は、「ルールに沿って診断しました」と一言添える。

## 変更の計画

```markdown
### {ラベル／フォルダ／名前／共有ステップ} の変更（{N} 件）

| # | 対象 | 変更前 | 変更後 |
|---|---|---|---|
| 1 | [#{番号}]({URL}) {名前} | {今の状態} | {変更後の状態} |

- 影響：{例：一括実行「毎日」の対象が 12 件 → 15 件になります／実行順が変わるテストはありません}
- 画面で行っていただくこと：{例：ラベル「daily」の作成（設定 > テストケースラベル）}

この内容で変更してよいですか？（一部だけでも構いません）
```

## 変更の記録

すべての変更が終わったら、元に戻すときに使えるよう、変更前と変更後を残す。

```markdown
### 変更の記録（{YYYY-MM-DD}）

| 種類 | 対象 | 変更前 | 変更後 |
|---|---|---|---|
| 名前 | #59 | Test | 宿泊予約_プランを選んで予約が完了する |
| ラベル | #61 | flaky, 作成中, 完成 | flaky, 完成 |
| フォルダ | #67 | / | /お問い合わせ |
```

## 完了の報告

```markdown
## 整理の結果

- やったこと：{例：ラベル 15 件の付け外し、フォルダ 3 個の作成と 12 件の移動、名前 6 件の変更}
- ルールのファイル：{作成した／更新した節／作成していない}
- 画面で行っていただくこと：
  - {例：一括実行「毎日」の実行対象を、ラベル「daily」に切り替える}
- まだ手を付けていないこと：{例：説明欄の記入（17件）、共有ステップの整理}

### 棚卸しの提案（削除はしていません）

**A. 削除をおすすめ**
| テストケース | 理由 |
|---|---|
| [#{番号}]({URL}) {名前} | {例：ステップ0件で、作ってから一度も更新されていない。一括実行で「成功」と数えられ、成功率を高く見せている} |

**B. 判断が必要（用途しだい）**
| テストケース | 理由 | 残すなら |
|---|---|---|
| | | |

**C. 残して直す**
| テストケース | 理由 |
|---|---|
| | |

削除の前に、ステップの控えをファイルに残せます（必要なら言ってください）。

### 気づいたこと（整理の範囲外）
- {例：#9 の URL に資格情報が直接書かれています。変数に移すことをおすすめします}

{変更の記録}
```

## 棚卸しの提案

完了の報告に必ず入れる。次の観点で見て、A〜C に分ける。

| 観点 | よくある区分 |
|---|---|
| ステップが 0 件のまま長く放置されている | A（作るつもりがあれば B） |
| ほかのテストとほとんど同じ（1行だけ違う、コピーのまま） | A か B（違いに意味があるかで分ける） |
| 何も確かめていない（Assert がない、URL を開くだけ） | B か C（確認の行を足せば意味がある） |
| 毎回失敗していて、直す予定がない | B（3か月ほど直さないままなら、次の棚卸しで A） |
| 名前から試しに作ったと分かる | A か B |
| 使われていない共有ステップ | このスキルでゴミ箱へ移せる（承認を得てから） |

- 理由には、事実（ステップ数、最後の更新日、どのテストと同じか）を書く。
- 動画やデモなど、テストとは別の用途で残していることがあるので、B には「残すなら」の列を付ける。

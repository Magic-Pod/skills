# 共有ステップ：重複のまとめと片付け

## 1. 重複ステップを見つける

1. 候補のテストを絞る。全テストのステップを読むと重いので、次の順に絞る。
   - 名前や要約（`ai_generated_summary`）が似ているテスト（同じ画面から始まる、同じ操作を含む）
   - 同じフォルダのテスト
   - ユーザーが指定したテスト
2. 候補のテストのステップを `get_test_case_detail` で読む（読み取りだけなら `start_session` は不要）。
3. 同じ手順の並びを探す。
   - 目安：**2つ以上のテストで、5行以上続く同じ手順**。ログイン・会員登録・カートに入れる、などが多い。
   - 入力する値だけが違う並びは、パラメータにすれば1つにまとめられる。
   - **UI 要素の名前やロケータが一致するとは限らない。** テストごとに画面を取り直していると、同じ操作でも名前（例：「カートボタン」と「button」）やロケータが違う。名前の一致で探さず、**同じ画面で同じ操作をしているか** で見つける。
   - そうした重複をまとめるときは、どれか1つのテスト（基準のテスト）の手順から共有ステップを作る。`create_shared_step` が、基準のテストの UI を自動で共有の UI にする（返り値の `shared_ui_ids`。2026-11-11 に Demo で確認）。
   - 置き換えたほかのテストは、**基準のテストの UI 要素とロケータで動く** ようになる。ロケータが違っていた場合は、計画の表にそのことを書き、置き換えたあとに実行して確かめるよう勧める。
   - コメント行（`//`）の書き方が違うだけの並びは、同じ手順として扱ってよい。
4. **すでに同じ内容の共有ステップがないか** を `list_shared_steps` と `get_shared_step` で確かめる。あれば、新しく作らずにそれを使う（手順3の「既存の共有ステップに寄せるとき」）。
5. **わざと共有ステップを使っていないテスト** は、置き換えの候補から外す。動画や教材で「共有ステップを使う前」を見せるためのものなど。名前（「直接記述」など）、ラベル（「動画用」など）、説明欄から判断し、迷ったらユーザーに聞く。
6. 置き換え先の共有ステップと1〜2行だけ違う（スクリーンショットの行が多い、など）ときは、置き換えると何が増える・減るかを計画に書いて承認を得る。

**パラメータの確かめ方**：共有ステップの中で `${email}` のような変数を使っているとき、それが共有ステップのパラメータか、テスト側の変数かは `get_shared_step` では分からない。`start_session` の返り値の「Most commonly used shared steps」の一覧（各共有ステップの Parameters が出る）か、`read_shared_step` で確かめる。どちらも `start_session` が要るので、置き換えの計画を作る段階で1件目のテストを開いて確かめる。

## 2. 計画を見せる

| # | 共有ステップの名前（案） | 中身（ステップの要約） | パラメータ | 使うテスト（範囲） |
|---|---|---|---|---|
| 1 | ログインする | URL を開く → メールアドレスとパスワードを入力 → ログインを押す → ホームの表示を確認（6行） | メールアドレス、パスワード | #45（3〜8行目）、#46（3〜8行目）、#47（5〜10行目） |

- 名前はルールの形に合わせる（ルールがなければ「動詞＋対象」を勧める。例：`ログインする`、`商品をカートに入れる`）。
- 置き場所のフォルダもあわせて示す（共有ステップが 10 個を超えるなら、機能ごとのフォルダに分ける）。
- 共有ステップを作る・置き換えるのは **デフォルトブランチだけ** でできる。変更はすぐにチーム全員のテストに反映されることを伝える。

## 3. 作って置き換える（承認を得てから）

**既存の共有ステップに寄せるとき** は、下の 1 を飛ばして、すべてのテストを 3 の手順（`edit_steps` で置き換え）で行う。動作確認（2）は、置き換えたテストのうち、置き換える前に安定して通っていたものを選ぶ。

**置き換える範囲の選び方**：`read_test_case` の `command` を見て、共有ステップの最初の行と最後の行に当たる `ref` を選ぶ。条件分岐の終わり（`statement_end`）やコメント・空行も、共有ステップの中身に含まれていれば範囲に入れる。`get_test_case_detail` の読みやすい形では、`statement_end` が「End branch」、空行が空の行に見えるので、行を数えるとずれやすい。

1. **1件目のテスト** で `start_session` → `read_test_case`（ステップの `ref` を取る）→ `create_shared_step`（`from_ref`〜`to_ref`、`name`、必要なら `params`、`folder_number`）。そのテストの範囲は、共有ステップの呼び出しに自動で置き換わる。
2. 1件目のテストが動くことを確かめる。`manage_device`（`start`）→ `execute_partial_steps` で実行するか、ユーザーに画面で1回実行してもらう。
   - 実行するとクラウド端末や AI クレジットを使うことがあるので、実行の前に聞く。
   - 共有ステップを作ったり置き換えたりすると、ステップの `ref` が付け直される。実行の前に `read_test_case`（`force_refresh: true`）で取り直す。
   - 失敗しても `execute_partial_steps` の返り値には理由が出ないことがある。`get_test_run`（`kind: "result"`）で、どの行で何が起きたかを確かめる。
   - 失敗した行が共有ステップより後で、置き換えと関係ない原因（日付に依存する操作など）なら、そう伝えて置き換えは成功として扱う。テストそのものの修正はこのスキルでは行わない。
   - 置き換えたテストが、置き換える前から毎回失敗しているものだけなら、実行しても置き換えの良し悪しは判断できない。通るテストがあればそれだけを実行し、残りは次の一括実行の結果で見てもらう。
   - 終わったら `manage_device`（`terminate`）でクラウド端末を止める。
3. **残りのテスト** は、1件ずつ `start_session` → `read_test_case` → `edit_steps`（`operation: "replace"`）で、同じ範囲を共有ステップの呼び出しに置き換える。
   - 共有ステップの呼び出しは、次の形で書く（`get_command_definition` には `shared_step` がないので、この形を使う。`start_session` の説明にも同じ形が載っている）。
     ```json
     {"command": "shared_step", "params": {"shared_step_number": 419351, "args": {}}}
     ```
     パラメータがあれば `args` に `{"パラメータ名": "値"}` で渡す。UI 要素を渡すときは `{"uiId": "...", "uiElementId": ...}` の形。
   - パラメータには、置き換える前のステップに入っていた値を渡す（テストごとに違う値を正しく渡す）。
4. 置き換えたテストの一覧を見せ、一括実行で確かめるよう勧める。

注意：

- `start_session` の返り値は長い（MagicPod の使い方の説明とコマンドの一覧を毎回含み、1回で数万字）。読むだけなら `get_test_case_detail` を使い、`start_session` は変更するテストだけに使う。置き換えるテストが 10 件を超えるときは、区切りごとに進める。
- 置き換えたあと、`get_shared_step` の `referencing_test_cases` で、置き換えたテストがすべて並んでいるかを確かめる。
- 置き換えの途中で失敗したら、そこで止めて、どのテストまで置き換えたかを伝える。
- 共有ステップから参照できるのは、共有の UI だけ。置き換える範囲が共有でない UI を使っていると保存できない。その場合は、無理に進めずユーザーに伝える。

## 4. 共有ステップを片付ける

`list_shared_steps`（`depth: null`）で一覧を取り、次のものを挙げる。

| 種類 | 見つけ方 | 提案 |
|---|---|---|
| 使われていない | `test_case_count` と `shared_step_count` がどちらも 0 | ゴミ箱へ移す（`manage_shared_steps`、`action: "delete_shared_step"`）。ゴミ箱から戻せる |
| 似ている・重複している | 名前が似ている、`get_shared_step` で中身を比べると同じ | どちらかに寄せる。寄せる側を使っているテストの呼び出しを置き換えてから、使われなくなった方をゴミ箱へ |
| 名前がルールから外れている | 命名規則と比べる | 名前の変更（`action: "edit_shared_step_info"`） |
| フォルダがない・散らかっている | 一番上に 10 個以上ある | 機能ごとのフォルダに分ける（`create_folder`、`move`） |

- 使われていない共有ステップでも、作りかけのことがある。ゴミ箱へ移す前に、ユーザーに確認する。
- 共有ステップのフォルダの削除（`delete_folder`）は元に戻せない。空のフォルダだけ、承認を得てから行う。

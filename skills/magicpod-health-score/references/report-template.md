# 結果のまとめ方

チャットで返す。長くなりすぎないよう、表は必要なものだけにする。

## 改善提案（モード B）

```markdown
## ヘルススコア：{表示名}（{組織名}/{プロジェクト名}）

**{スコア} 点（{グリーン／オレンジ／レッド}）** ／ 前の週から {+n / −n / 変化なし}
いちばん効く一手：{提案1の要約}（見込み +{n} 点）

### 内訳

| 項目 | 点数 / 満点 | メモ |
|---|---|---|
| 実行頻度 | x / 35 | {例：一括実行が週0回。スケジュール実行は {日付} を最後に止まっている} |
| 失敗率 | x / 35 | |
| 共有ステップ | x / 8 | |
| 安定したロケータ | x / 8 | |
| テスト数 | x / 6 | |
| テストの長さ | x / 5 | |
| メンバー数 | x / 3 | |

### 推移と、その理由（直近4週）

{週ごとのスコアを1行で。例：38 → 41 → 52 → 64}
{動いた・動かなかった理由。例：スケジュール実行が止まってから変化なし／10/26 の週に失敗率が下がった}

### 提案（優先順）

1. **{やること}**
   - 理由：{なぜ減点されているか}
   - 見込み：{項目} {x} → {y} 点（目安）
   - 注意：{あれば。例：一括実行から外すと実行頻度が下がる}
2. ...

{すべて実施した場合の見込み：{x} → {y} 点（目安）。失敗率が分からない場合は幅で}

### 次のステップ

どの提案から進めますか？
- {提案1}：{つなぎ先のスキル、またはヘルプ記事}
- ...

改善を始めたら、1週間後にもう一度スコアを確認しましょう。
```

## 維持（モード C）

```markdown
## ヘルススコア：{表示名}（{組織名}/{プロジェクト名}）

**{スコア} 点（グリーン）** ／ 前の週から {+n / −n / 変化なし}
**グリーンまでの余裕：{スコア − 80} 点**。{例：毎日失敗するテストがあと 2 件増えるか、成功率が 62% 前後を下回ると 80 点を割る見込み}
いちばん効く一手：{提案1の要約}（見込み +{n} 点）

### 推移と、その理由（直近4週）

{例：84 → 84 → 81 → 83。10/26 の週は失敗率が下がった}

### 下がり始めている・余裕の少ない項目

- {項目}：{今の状態と、何が起きるとどれだけ下がるか}

### 維持の習慣のチェック

| 習慣 | 状態 | 根拠 |
|---|---|---|
| 平日毎日の一括実行 | できている／できていない | {例：毎日 15:00 にスケジュール実行} |
| 失敗を翌日に持ち越さない | | {例：同じテストが1か月以上毎日失敗している} |
| 週1回のスコア確認 | 分からない（ユーザーに確認） | |

### 提案（1〜3 件）

1. **{やること}**
   - 理由：...
   - 見込み：...（目安）

### 次のステップ

どの提案から進めますか？ ...
```

## 目標設計（モード A）

```markdown
## 3か月の目標：{表示名}（{プロジェクト名}）

**今のスコア**：{スコア} 点（{色}）／ 直近4週 {推移}
{今の状態を1〜2行。例：一括実行が止まっている、試しに作ったテストが 10 件ある}
いちばん効く一手：{例：毎日の一括実行の仕組みをつくり、試しに作ったテストを整理する}

**目標**：{今日から3か月後の日付}までに、毎日安定して成功するテスト 8 件 ／ ヘルススコアのグリーン

| 時期 | 到達目標 | やること | スコアの目安 |
|---|---|---|---|
| 1か月目（〜{日付}） | | | |
| 2か月目（〜{日付}） | | | |
| 3か月目（〜{日付}） | | | |

点数は計算の仕組みから見た目安で、保証ではありません。

**最初の 3 件の候補**：...
**今は自動化しないもの**：...
**仮置きした前提**：{質問で分からなかったこと}

### 今週やること

1. ...

### 次のステップ

どの提案から進めますか？
- {やること}：{つなぎ先のスキル、またはヘルプ記事}

始めたら、1週間後にこのスキルでスコアの変化を確認しましょう。
```

A と B を組み合わせるとき（導入中でスコアが低い）は、モード A の形に、B の「内訳」と「提案（優先順）」を「今週やること」の前に入れる。

## 複数のプロジェクト

```markdown
## ヘルススコア：{組織名}（{n} プロジェクト）

{結論を1〜2行。例：グリーンは 1 つ。ほかは一括実行が週0回}

| プロジェクト（表示名（名前）） | スコア | 色 | ひとこと |
|---|---|---|---|
| ... | | | |

{一括実行が週0回のプロジェクトがあるとき：デモ・検証用か、運用しているものかを聞く一文。ここでいったん止めて答えを待つ}
```

答えをもらったら、表を「運用中」と「デモ・検証用（提案なし）」に分けて出し直し、運用中のプロジェクトのうち深く見るものごとに、モード B／C の形を続ける。

## 書き方の注意

- 点数の見込みは目安であり、保証ではないと分かるように書く。
- プロジェクトは `表示名（名前）` の形で書く。表示名と名前が同じなら1つでよい。
- テストケースへのリンクは `https://app.magicpod.com/{組織名}/{プロジェクト名}/{番号}/` で組み立てる。
- ヘルプ記事のリンクは `help-articles.md` の ID から組み立てる。
- MagicPod の画面の言葉（一括実行、共有ステップ、ロケータ、アナリティクスタブ）にそろえる。
